## PART I: SOFTWARE REQUIREMENTS SPECIFICATION (SRS)

### 1. Introduction
**1.1 Purpose:** 
The purpose of GRIMOIRE is to eliminate the fragmentation inherent in modern self-taught learning. It acts as an autonomous AI-orchestrated learning environment using a distributed swarm of 18 separate agents to dynamically build, adapt, teach, grade, and map learners to mastery.

**1.2 Scope:** 
The system operates as a Next.js web client connecting to a Python/FastAPI microservices gateway. It spans curriculum generation (Planner), audio/visual technical interviewing (Interview), YouTube data extraction (Space), context-aware retrieval (Doubt Assistant), Reinforcement Learning (RL Controller), and Cryptography (Verifiable Badges).

### 2. User Classes and Characteristics
- **Learners (Primary)**: Require high-usability graphical interfaces, fast generation, responsive voice models, and gamified progress mapping.
- **Instructors/SysAdmins (Secondary)**: Require access to system telemetry, logging infrastructure (`ActivityLogger`), and quota management (`ModelRouter`).
- **AI Agents**: Internal sub-system users that fetch raw data to synthesize human-readable assets (e.g. `Retriever` fetching YouTube data for the `Composer`).

### 3. Functional Requirements (FR)

#### FR1: Adaptive Roadmap Generation (The `Planner` Agent)
- **FR1.1**: The system MUST evaluate the user’s current knowledge level through an interactive diagnostic quiz generated by `/api/v1/agents/planner/prerequisites`.
- **FR1.2**: If gaps are detected, the system MUST dynamically append bridging modules to the final generated learning path.
- **FR1.3**: The system MUST return a strictly constrained JSON matching `roadmap.schema.json`, consisting of 4-30 modules containing unique topics, expected hours, and at least two distinct learning URLs (YouTube videos/Docs) enforced via `search_query` permutations to prevent 404 hallucinations.

#### FR2: Real-time Multimodal Voice AI Interview (`Interview` Agent)
- **FR2.1**: The system MUST accept PDF or Image resumes, parsing them via `pypdf` or Groq Vision models dynamically.
- **FR2.2**: The system MUST leverage the native Web Speech API (Client-Side STT/TTS) to facilitate bi-directional voice logic.
- **FR2.3**: The backend MUST analyze base64 webcam frames at `/interview/{id}/analysis` using `mediapipe` to capture `eye_contact` ratios, lip `smile_detected` booleans, and physical `posture_score`.
- **FR2.4**: The system MUST aggregate text transcriptions + non-verbal scores and feed them to an LLM logic chain to grade the user out of 5 across multiple technical and soft-skill domains.

#### FR3: Context-Aware Retrieval & Note Intelligence (`Doubt` & `Notes` Agents)
- **FR3.1**: The system MUST maintain a WebSocket connection (`/ws/doubt-assistant`) yielding low-latency delta chunks to the DOM for study interaction.
- **FR3.2**: The system MUST index summarized transcripts into persistent `ChromaDB` localized storage.
- **FR3.3**: The Note Intelligence agent MUST slice user markdown notes into Priority bands (High/Medium/Low) and auto-generate theoretical evaluations appended to Firebase `user_notes`.

#### FR4: Gamification and Reinforcement Learning (`RL Controller`)
- **FR4.1**: The system MUST process recent quiz scores and hint utilization rates through a Rule-Based contextual bandit.
- **FR4.2**: If `avg_score <= 0.5` or `hints_used >= 5`, the system emits an `easier` configuration, forcing the `Composer` to simplify upcoming lessons using Bloom's Taxonomy principles.
- **FR4.3**: Upon milestone completions, the `Badge` agent MUST emit Ed25519 hash-validated cryptographic seals.

### 4. Non-Functional Requirements (NFR)
- **NFR1: High-Availability Failover**: The `ModelRouter` MUST automatically fallback from Groq -> Gemini -> Local LLM (Ollama) during runtime if `429 ResourceExhausted` is raised. Key arrays must rotate based on a modulo index operation.
- **NFR2: Sub-second Latency for Voice**: Interactive agents (Interview) MUST be routed to ultra-low-latency APIs (Groq Llama 3) to prevent conversational overlap latency.
- **NFR3: Gateway Resilience**: The FastAPI `main.py` instance MUST utilize `TrustedHostMiddleware` allowing wildcard host mapping `["*"]` to support PaaS deployments on Railway, alongside `slowapi` boundaries. 
- **NFR4: Zero Cold Boot Latency on Storage**: The `lifespan` handler of the Gateway MUST pre-initialize the `VectorStore` during FastAPI setup to avoid the massive blocking penalty of `import chromadb` dynamically during initial user inference.

## PART III: DEEP ARCHITECTURE & LLM ORCHESTRATION (`backend/shared/models/model_router.py`)

To prevent token-cost explosions and maximize performance, GRIMOIRE routes agent queries using an advanced asynchronous `ModelRouter` handling fallback cascading.

### 1. The Routing Strategy
- **Groq (Default for interactive layers)**: Used heavily by the `Interview` and `Podcast` agents. Prioritizes sub-second inference. If images are provided and standard Groq models fail, it auto-defaults to `meta-llama/llama-4-scout-17b-16e-instruct` to process vision.
- **Gemini (Default for heavy planning & RAG)**: Handles `Planner`, `Composer`, `Retriever`, `Assessment`. It leverages Gemini's `caching.CachedContent` API with a 60-minute TTL for `system_prompts` exceeding 1000 characters to drastically lower latency on massive agent instructions.
- **Local LLM / Ollama (Fallback/Simple tasks)**: Handles the `Summarize` and `Badge` validation agents to perform zero-cost computation.

### 2. Local Context Caching & Key Rotation
The router maintains an in-memory `_response_cache` leveraging `MD5` hashing on `(prompt + system_prompt + max_tokens)` with a 300-second TTL. This instantly solves redundant identical queries when users fast-click UI components without bouncing to Groq/Gemini. It automatically rotates through an array of Gemini keys via `self.settings.gemini_api_keys` to bypass `429 ResourceExhausted` quota limits seamlessly using modulo index rotation: `(start_index + i) % total_keys`.

## PART IV: CORE AGENT ALGORITHMS & MATHEMATICAL MODELS

### 1. Adaptive Roadmap Planner (`services/planner`)
**Trigger:** Next.js posts variables (`user_goal`, `availability`, `prerequisite_updates`) to `/v1/agents/planner`.
**Internal Logic:**
- Uses the prompt defined in `shared/prompts/planner.md`. 
- **Anti-Hallucination Guardrail**: The prompt rigorously enforces the AI to use specific URL pattern structures like `https://www.youtube.com/results?search_query=TOPIC+tutorial` to ensure generated video links never 404.
- **Variable Module Depth**: The AI is instructed dynamically: "Simple topics: 4-8 modules", "Complex topics: 20-30+ modules".

### 2. Reinforcement Learning Controller (`services/rl_controller`)
**Mathematical Algorithm:**
```python
avg_score = sum(recent_quiz_scores) / len(recent_quiz_scores)
if avg_score >= 0.85 and hints_used <= 1:
    action = "harder"
    confidence = min(0.9, avg_score)
elif avg_score <= 0.5 or hints_used >= 5:
    action = "easier"
    confidence = 0.8  # Increases scaffolding
else:
    action = "same"
```
The controller scales Bloom's Taxonomy logic to rewrite upcoming lessons. If it outputs `easier`, the Composer breaks down upcoming modules into smaller atoms; if `harder`, it reduces instructional text and introduces system design complexity. It intercepts natively into `/v1/daily-plan/{user_id}` forming a unique object appended underneath `rl_recommendation`.

### 3. Live Voice AI Interview (`services/interview`) & Computer Vision
**Workflow:**
1. **Resume Processing**: The user uploads a resume. If it's a PDF, GRIMOIRE uses `pypdf`. If it is an image, the `ModelRouter` leverages vision endpoints.
2. **Audio I/O**: `Web Speech API` natively performs STT/TTS on the client side.
3. **Computer Vision Endpoint (`/interview/{session_id}/analysis`)**: 
   - The frontend pushes base64 frames iteratively to the backend.
   - The `VideoAnalyzer` uses `mediapipe` Face Mesh and Body Pose estimation alongside `opencv-python-headless` to calculate spatial `eye_contact` ratios, lip-curve `smile_detected` booleans, and shoulder alignment `posture_score`.
4. **Final Assessment**: The aggregated `non_verbal_summary` is fed into Groq alongside the entire chat transcript to grade Technical Knowledge and Non-Verbal Communication individually out of 5.0.

### 4. YouTube Space Intelligence (`frontend/app/space/page.tsx` & Backend)
**The UI Flow & Backend RAG execution:**
- Front-end regex parses standard `youtube.com/watch` or `youtu.be` links. 
- State constructs a randomized session `user_{Math.random()}`.
- Backend `v1/functions/execute` routes the `fetch_transcript` function via `yt-dlp`. 
- Extracts keywords passively matching regex ranges omitting words (`this`, `that`, `will`) to map topics.
- Passes truncated context (clamped to 20,000 characters of transcript) + title into the `/api/v1/space/chat` RAG pipeline.

## PART V: SYSTEM DATA SCHEMAS AND PERSISTENCE 

### 1. Core Schema Structures `shared/schemas/`
GRIMOIRE relies heavily on strict JSON outputs requested manually from the LLMs logic gates.

**The `roadmap.schema.json` Constraints:**
When the Planner generates a syllabus, the output must rigidly conform to:
- `estimated_weeks`, `total_hours`
- `modules` (Array): Containing `title`, `description`, `learning_outcomes`, `difficulty`, `key_concepts`.
- `lessons` (Inner Array): Must contain minimal 2 unique multimedia resources per module marked with `type: ["youtube", "article", "documentation"]`.

**The `badge.schema.json` Constraints:**
- Verifiable hash logic containing `name`, `criteria`, `timestamp`, `signature` (Ed25519 payload sealing).

### 2. The Persistence Layer (`Firebase & ChromaDB`)
**Firestore Collections (`firebase_client.py`)**:
- `users`: Core profile context (`save_user_profile()`).
- `roadmaps`: Complete AI-generated curriculum trees.
- `lessons`: Individual dynamically generated text explanations.
- `assessment_results`: Moving-average quiz outcomes directly accessed by the RL Controller. LIMIT 50 descending.
- `user_notes`: Isolated chunks produced by the notes_intelligence agent.
- `conversations/{id}/video_analysis`: Transient document streams recording webcam sentiment for post-calculation.

**ChromaDB Vector Collections**:
- `interview_questions`: Highly indexed, dense vectors representing technical question-and-answer pairs extracted to prevent redundant questions.
- `document_chunks`: General RAG database containing Wikipedia, YouTube transcripts, and PDF slices used by the `Doubt` WebSockets.

## PART VII: EXECUTION VARIABLES & END-TO-END JOURNEY

### 1. End-To-End Logical Journey
1. **Onboarding**: User creates an account via `Clerk` (`frontend/app/sign-up`). Core config triggers `backend/v1/user/profile` storing baseline metadata on Firebase.
2. **Syllabus Execution**: User visits `/roadmap` stating they wish to learn "Tensorflow". 
3. **Diagnostics**: `/api/v1/agents/planner/prerequisites` tests Python math syntax iteratively to determine existing knowledge gaps.
4. **Agentic Synthesis**: Results are posted to `planner`, firing MD5 Cached Prompts over Groq/Gemini to fetch JSON definitions. The system invokes `roadmap.schema.json` forcing minimum two unique links mapping.
5. **Continuous Learning**: As the user executes `lesson/page.tsx`, the `<VideoChat>` widget opens Websocket protocols natively referencing `document_chunks`.
6. **Difficulty Interventions**: Every time the UI reports `assessment_results`, the `rl_controller` evaluates hint usage (`hints_used >= 5`) dynamically restructuring future `composer` loads simpler via `/v1/daily-plan/{user_id}` endpoints.
7. **Synthesis**: The `podcast` route compresses the week's documentation to an Edge-TTS `.mp3` output generated to `.assets/`.
8. **Evaluation**: User tests via `interview/page.tsx`. `opencv` logs frame stability over `mediapipe`, resulting in an algorithmic `badge` being granted to `/u/[user_id]`.

Run `.\start_all.ps1`. This natively boots Python virtual environments and Node workspaces sequentially.
